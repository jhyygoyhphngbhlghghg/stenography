# Ограничения решения

Пункт 5 отчётного материала. Здесь то, что реально работает, то, что не
работает, и формулировки, которыми мы защищаемся. Числа — только измеренные;
источник каждой строки в `docs/TEST_RESULTS.md`.

## Поддерживаемые условия

- Android 9.0+ (minSdk 28; бриф допускает 26–28). Сборка под arm64-v8a,
  armeabi-v7a, x86_64.
- Вход: локальный файл (WAV / M4A / MP3 через SAF) **или** запись микрофоном
  приложения; всё сводится к 16 кГц моно.
- Выход: список реплик в UI + JSON брифа (`speaker_id`, `start_ms`,
  `end_ms`, `text`) в файл через SAF, либо «Поделиться».
- Офлайн-стенография работает в авиарежиме: модели лежат в APK
  (`assets/models`, ≈114 МиБ) и распаковываются в `filesDir` при первом
  запуске.
- PresentConnect — отдельный flavor с сетью, ≤20 потоков, optional.

## Заявка защиты = DEMO_STAGE6

Шесть русскоговорящих спикеров на сцене, **один** микрофон телефона, места
3–6 м, очередь реплик с лёгким перекрытием в конце, большая комната, средний
babble/HVAC, характер телефонного микрофона (band-limit, компрессия,
ослабление по расстоянию, реверберация). Это «идеальные» условия распознавания,
не студия.

| место | спикер | Hex WER baseline | после K≤6 + интонац. punct |
|---|---|---|---|
| 3.0 м | speaker_1 | 0.2857 | 0.2143 |
| 3.6 м | speaker_2 | 0.5833 | 0.3333 |
| 4.2 м | speaker_3 | 1.0000 | 1.0000 |
| 4.8 м | speaker_4 | 1.0000 | 0.9000 |
| 5.4 м | speaker_5 | 1.0000 (пропущен) | 1.0000 (не сопоставлен) |
| 6.0 м | speaker_6 | 1.0000 | 0.6923 |
| **aggregate** | — | **0.7794** | **0.6471** |

DER 0.2760, JER 0.5454, RTF 0.1173 (host Linux), спикеров в гипотезе **6 / 6**.

## Что честно не работает

- **Дальние места 4.2–5.4 м.** Реплики теряются или распознаются пустыми;
  speaker_5 не восстановлен. Усиление (`FarFieldGain`) и спектральный EQ
  (`PhoneDistanceEq`, 250–4500 Hz) **заморожены**: ни то ни другое не вернуло
  Hex WER 0.7794 на этом миксе, и дальнейшая подстройка чисел под фикстуру —
  это подгонка, а не решение.
- **Перекрытие речи** смазывает диаризацию; демо-запись делается с явной
  сменой реплик.
- **Один канал, один телефон.** Диаризация «коктейля» из 20 говорящих в
  комнате — измеренный провал (Path A: 1/20, DER 0.95), не заявка.
- **English — best-effort.** Zipformer-ru RU-first; для EN есть Whisper tiny
  как alternate модель, но не вторая полноценная цепочка.
- **Пунктуация.** Запятые ставятся по интонации/паузе, а не по школьным
  правилам (это и есть замоченное правило скоринга); на тексте Zipformer
  эвристические запятые срабатывают не везде — в замере speaker_1 остался
  только терминальный `.` плюс три удалённые запятые.
- **Скорость.** RTF 0.1173 — это host Linux (sherpa-onnx 2.0.1, x86_64).
  Он-девайс RTF на демо-телефоне ещё не замерялся.
- **Он-девайс проверка не выполнена.** `scripts/device-sideload-probe.sh`
  готов, но нужен живой телефон (Nothing-класс) — это human-действие.
- **Замер на последнем тибе не прогнан.** Строка K≤6 измерена на Impl
  `3c3f9ce`; тип `ab20d83` (не сливать s2/s3 под капом + карты тихих дальних
  мест) ещё не переоценён Eval.
- Долгое аудио без VAD-чанков деградирует; VAD обязателен.
- NNAPI у OEM плавает — провайдер по умолчанию CPU.

## Формулировки на защите

Нельзя говорить:

- «WER_main = 0» как результат комнаты;
- «усиление/EQ вернули дальние места»;
- «Path B ≤20 — это наше демо»;
- «WORST_CASE / EDGE_* чистые WER/DER» (WORST_CASE: WER main 0.9130,
  DER 0.25ms-вариант 1.2985 — это FAIL);
- «жёсткий BAND_LIMITED на привязанных местах — это фикс» (он мягкий, ASR
  всё равно идёт);
- «диаризация дала 6 спикеров» без замера — было 12/6, стало 6/6 после
  хард-капа, и это измерено на хосте.

Можно говорить:

> Офлайн стенографист на одном телефоне: VAD → диаризация → Zipformer-ru →
> локальная LLM. Последний прогон Hex WER 0.6471 при DER 0.2760, гипотеза
> 6/6 спикеров; дальние места пока пустые. Пунктуация учитывается в скоринге,
> запятые по интонации, `ё`/`е` не наказывается. PresentConnect ≤20 —
> опциональный режим.

## Правила скоринга, которые мы зафиксировали

- Пунктуация входит в точность транскрипции (Mikhail Grigorev, Hex.Team,
  2026-11-06).
- Запятые следуют интонации говорящего, а не орфографии.
- `ё` ↔ `е` не учитывается. Нормализация: `scripts/eval_metrics.py`
  (keep-punct + fold), а не стандартный strip-punct WER из `eval/`.

## Что мы не делаем (п. 10 брифа)

- Аудио не уходит наружу: нет cloud ASR, cloud diarization, cloud LLM.
- Вычисления не выполняются на удалённом сервере. Хостовые прогоны
  (`artifacts/eval/`) — это **наши** замеры для отчётности, не путь обработки
  в приложении; в приложении весь пайплайн локальный.
- Нет подмены расшифровки заранее подготовленным текстом: `StubStenoPipeline`
  помечен в UI как stub и судьям не показывается; `IdentityLlmPostPass`
  остаётся тестовым дублёром, реальный путь — GGUF.
- Picovoice/Cheetah/Leopard (AccessKey) не используются; OEM
  `SpeechRecognizer` не является зависимостью.

## Лицензионные ограничения

- pyannote segmentation-3.0: веса MIT, но HF-репозиторий gated — мы берём
  копию из релизного тарбала sherpa и сохраняем атрибуцию (`NOTICE.md`).
- 3D-Speaker ERes2Net и Silero VAD: свои лицензии, редистрибуция через
  sherpa-onnx; атрибуция в `NOTICE.md`.
- Qwen2-0.5B-Instruct — Apache-2.0; llama-android — MIT; sherpa-onnx —
  Apache-2.0.
- Модели в git не кладём (`.gitignore`), APK и видео — тоже; сдаём как
  release-ассеты.

## Что не входит в версию

- Web FE и бэкенд презентации (отдельный трек).
- Обучение/дообучение ASR, pyannote Python на телефоне.
- Word-level таймстемпы, переименование/слияние спикеров в UI, редактирование
  и перепрогон отдельного фрагмента (Ultra Pro Max из брифа).
- whisper.cpp как основной движок, облачный fallback.

## Риски демонстрации

- Забыть распаковать модели до авиарежима → stub на защите. Чеклист и
  распознавание состояния — в UI (`pipeline = stub`, `LLM: …`).
- 353 МиБ GGUF внутри APK: если собираем `-PembedLlm=true`, артефакт
  становится ~530 МиБ — скачивать заранее и по Wi-Fi.
- На armeabi-v8a-32/x86_64 GGUF-движок отсутствует (AAR только arm64) →
  LLM-пост-проход деградирует до интонационной эвристики, UI это пишет.
