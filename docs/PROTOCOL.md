# Протокол передачи

## Цели

Шаблон хакатона предполагает acoustic transfer — приём звука динамиком второго
устройства. **Мы этот протокол не используем**: у нас речь снимается
микрофоном того же телефона, который её и обрабатывает, поэтому ни
«физического уровня», ни контрольных сумм принятого файла в нашем смысле нет.

Документ описывает то, что реально передаётся по проводам и в файлах:

- пайплайн аудио → JSON на устройстве;
- сетевой контракт с презентацией (Path B, `present-connect/1`).

## Физический уровень

Не применимо: между устройствами не передаётся звук. Акустический канал
используется только на входе — микрофон телефона в комнате (сценарий
`DEMO_STAGE6`: шесть говорящих, один микрофон, места 3–6 м).

Аудио не покидает устройство ни в каком виде: сервер не принимает PCM и не
распознаёт речь.

## Формат передачи

Единственный обязательный формат — экспорт брифа, четыре ключа и ничего
лишнего:

```json
{ "transcript": [ { "speaker_id": "speaker_1", "start_ms": 1250, "end_ms": 4380, "text": "Добрый день!" } ] }
```

Схема и правила — `docs/JSON.md`; проверка —
`python3 scripts/verify-transcript-json.py <export.json>`.

Внутренний формат статусов и чекпоинтов — `docs/PRESENT_CONNECT.md` §3–§5.

## Установление и завершение передачи

Телефон (Path B, если она включена) поднимает соединение POST
`/v1/workers/register` → получает `ws_url`, затем `hello` с протоколом и
списком моделей, дальше пушит `transcript.final` / `phone.status`. Завершение —
`demo.end` с пульта или потеря сокета. Полностью — `docs/PRESENT_CONNECT.md` §2,
§4, §6.

Для офлайн-сценария (основной демо-режим) установки соединения нет вообще:
авиарежим, файл или микрофон → JSON в файл через SAF.

## Синхронизация

Чекпоинт показа — монополия пульта: `checkpoint.set / step / goto` меняют
`slide_index` и `revision`; экраны получают обновление по WS и опросом
`GET /v1/presentation` на 1–2 Гц (контракт §5). Экраны — read-only сокеты,
уйти вперёд или назад зритель не может.

## Ошибки и восстановление

`BAD_PROTOCOL`, `BAD_MESSAGE`, `BAD_JSON`, `UNAUTHORIZED`, `SUPERSEDED` — см.
контракт §4. 45 с молчания телефона — переход в `fallback` с явным баннером
«показана запись, не результат модели»; резервные и симулированные строки
помечены `source` и **не** попадают в экспорт.

## Совместимость

`present-connect/1`, Android minSdk 28 (role `worker` принимается как алиас
`phone`, чтобы flavor не требовал отдельного контракта), браузеры экранов —
современные Chrome/Safari/Firefox с WebSocket.

## Пример

Один полный цикл — `docs/PRESENT_CONNECT.md` §7 и `npm run sim:phone` в
`src/web/backend` (симулятор телефона против реального сервера).
